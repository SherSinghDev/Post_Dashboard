# 🏥 BSRF India — Post Dashboard: Full Project Analysis

## Overview

This is a **full-stack admin dashboard** for an Indian NGO called **BSRF (Bhartiya Samaj Raksha Foundation)**. It's a server-rendered web application built to manage the organization's healthcare operations, membership management, order/parcel logistics, and staff coordination.

**Domain**: `bsrfindia.com`  
**Server Port**: `3200`  
**Database**: MongoDB (`parceldb`) hosted on `72.60.101.162:27017`

---

## Tech Stack

| Layer | Technology |
|-------|-----------|
| **Runtime** | Node.js |
| **Framework** | Express.js v5.1 |
| **Templating** | EJS (server-side rendering) |
| **Database** | MongoDB via Mongoose v8.18 |
| **Auth** | Express-session (cookie-based) |
| **File Upload** | Multer v2 (Excel files → `./src/assets/uploads/excelfiles`) |
| **Payments** | Razorpay (live keys) |
| **WhatsApp API** | Bol7 (`chat.bol7.com`) for automated notifications |
| **Excel Parsing** | `xlsx`, `xls-to-json`, `xls-to-json-lc` |
| **Dev Tool** | Nodemon |

## Core Business Modules

### 1. 👥 User & Membership Management
- **Users** have roles, positions, referral codes (`TL-XXXXXX`), and a hierarchical team system (`parentUser`, `teamLeaderId`)
- **Membership tiers**: ₹365/year, ₹500 lifetime, ₹865 combo
- **Applications** flow: Submit → Pending → Approved/Cancelled
- Support for multiple payment modes (UPI, bank transfer, cheque, cash)
- **Rojgaar (Employment)** applications — separate model but identical schema to membership applications

### 2. 🏥 Patient & Teleconsultation
- **Patient registration** with tracking IDs (`TRK-YYYYMMDD-RANDOM`)
- **Patient intake forms** — 6 form types (`form1`–`form6`), each assigned to a specific doctor
- Multi-stage status tracking: `patientStatus`, `doctorStatus`, `supportStatus`, `officeStatus`, `adminStatus`, `postOfficeStatus`, `trackingIdStatus`, `deliveryStatus`
- Medical report uploads

### 3. 📦 Order & Shipping Management
- **Patient Orders** — the most complex module (53KB controller, 111KB view)
- Integrated with **Proship** and **Smartship** shipping providers via webhooks
- Full order lifecycle: pickup → in transit → out for delivery → delivered
- AWB (Airway Bill) tracking
- Detailed schemas for pickup, delivery, return addresses, courier info, and shipment dimensions

### 4. 💊 Stock/Inventory Management
- **23 Ayurvedic/wellness product categories**: OrthoCare, DetoxCare, DiabetesCare, HeartCare, EyeCare, HairCare, SkinCare, NeuroCare, etc.
- Per-user stock allocation (linked to `userId`)
- Stock transfer transactions between users
- Money transactions tied to stock movements

### 5. 🎫 Support Ticket System
- Categories: Parcel Delay, Lost Parcel, Payment Issue, Pickup Issue, Return Issue, Other
- Priority levels: LOW, MEDIUM, HIGH
- Status workflow: OPEN → CALLING → IN_PROGRESS → RESOLVED/ESCALATED → CLOSED
- Call logging with outcome tracking (CONNECTED, NO_ANSWER, BUSY, INVALID)
- Support agent management with availability status

### 6. 💰 Payments
- **Razorpay integration** (live environment) for membership payments
- Payment statuses: CREATED → SUCCESS/FAILED
- Transaction records between sender and receiver

### 7. 📋 Jobs Portal
- Job applications with approval workflow (Unverified → Approved)
- Indian mobile number and PIN code validation

### 8. 📱 WhatsApp Notifications
- Automated messages via **Bol7 API** (`chat.bol7.com`)
- Sender number: `917417271707`
- Template-based notifications for:
  - In Transit (`907900041733412`)
  - Out for Delivery (`1444085863745042`)
  - Delivered (`2717556531914471`)
  - Dispatched (`2226838111392141`)

## Observations & Notes

> [!IMPORTANT]
> **Security Concerns**
> - MongoDB credentials are hardcoded in `db.js` (not using `.env`)
> - Express-session secret is a weak, hardcoded string (`^*&*(`)
> - CORS is set to `origin: '*'` (fully open)
> - Default user password is `1234`
> - Razorpay **live keys** are stored in `.env` (good), but the DB credentials are not

> [!NOTE]
> **Code Patterns**
> - The `modals/` directory is a typo — should be `models/`
> - `rojgaar.js` and `applications.js` models are nearly identical schemas
> - The `patientOrder` controller is by far the largest (53KB) — indicates heavy business logic for order management
> - Views are large monolithic EJS files (some exceeding 100KB), containing embedded CSS/JS
> - No API authentication/middleware for webhook endpoints

> [!TIP]
> **What this project does in plain language**
> BSRF India is an NGO that provides teleconsultation with doctors and ships Ayurvedic medicines to patients across India. This dashboard helps admins manage the full lifecycle: patient registration → doctor assignment → prescription → medicine packing → shipping (via Proship/Smartship) → delivery tracking → WhatsApp notifications. It also manages the organization's membership/volunteer network with a referral-based hierarchy and handles medicine stock inventory across team members.
